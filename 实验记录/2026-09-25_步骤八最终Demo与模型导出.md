# 阶段记录：步骤八最终 Demo 与模型导出

- 规格依据：原始 PDF 第 3 页“步骤八：最终 Demo 与模型导出”；配套详细说明第十六、十七节。
- 实现：`src/detector.py` 的 `AnimeFaceDetector.detect()` 接受非空 `uint8` OpenCV BGR 图像；灰度金字塔经 11 通道、三 Stage Cascade、NMS 得到原图半开框与末级分数，逐框以四轮 Ridge 回归 28 个原图坐标点。返回按分数降序的字典列表；无候选返回 `[]`。`demo.py` 写带绿色框、分数与红色点的图片以及同名 `.json`。不弹窗。
- 导出：`models/config.json` 指向 `models/step4_cascade.json`（54 棵 Depth-2 树及 Stage 阈值，SHA-256 `595983a793aa40ba1dfcaec704f24b15ac65ba7069887cdc9bc7d69630554194`）、`models/landmark_ridge4_visible_only.npz`（SHA-256 `1acf86d74815c7dd91ccbef8f89bd98cdaf992948e2aeb3812710c24ecdc9b50`）、`models/feature_definition.json` 和 `models/landmark28_schema.json`。配置含尺度因子 1.2、步长 1、NMS IoU 0.3、256×256 归一化、固定 split 数量、种子及来源文件 SHA-256。特征计算与关键点模型实现分别见 `src/channels11.py` 和 `src/landmark_regression.py`。
- 数据来源：检测模型为步骤四固定训练/validation 裁剪和困难负样本训练版本；关键点模型使用人工粗复核接受的 anime256 预标注，train/validation/test = 240/32/48，来源组不跨 split。划分种子 `experiment1-anime-face-v1`，Cascade 训练种子 `20260923`，关键点训练种子 `20260925`。模型选择依据为步骤六 validation 的可见点 NME；test 已被查看，不能称为盲测。

## 2026-09-25 误检诊断与后续改进决定

用户查看效果后指出仍有非脸部被识别为脸。本节只总结已经保存的运行结果，不声称完成新一轮训练或误报图片逐个复核。

- 复算命令：`.venv\Scripts\python.exe scripts/summarize_detector_errors.py`。输入为 `results/step4_stage_stats.json`、上述两份步骤八 validation/test 逐页 JSON、`datasets/manifests/normalized/manga109_faces.jsonl` 与 `datasets/annotations/corrected/step4_hard_negative_review.csv`；脚本写 `results/step8_error_diagnosis.json`，SHA-256 `9934aaeb7f9f9ab446c015a03e4782955b0bf4344c6151ab262a279bf442ce84`，内含全部输入 SHA-256。沿用原固定 split、页面选择和种子；此处只汇总，未改数据或模型。
- Cascade 的固定**裁剪 test 分类集**中，354 个背景窗口有 79 个通过全部 Stage，344 个人脸窗口有 304 个通过。这是裁剪分类统计，不能当作整页 IoU 指标。步骤四仅有 24 个困难负样本经人工复核并加入训练；另 216 个候选仍未复核、未用于训练。步骤四记录还显示那 24 个样本在回训后仍全部通过 Cascade，说明现有困难负样本覆盖与训练强度不足。其对本轮所有误报的具体贡献尚未逐图验证。
- **整页 IoU≥0.5**：test 八个不同作品共 85 个标注脸，原 Cascade 匹配 55 个、FP 34,850；当前 HOG 筛选后匹配 16 个、FP 149，额外少匹配 39 个。validation 对应为 73 个标注脸、原 Cascade 46 TP/31,834 FP、HOG 后 16 TP/177 FP。HOG 阈值改善 Precision 的同时明显牺牲 Recall；由于一对一匹配受候选排序影响，TP 差值是系统级变化，不能直接解释为 39 个特定框都被 HOG 删除。
- 尺度初筛：test 标注中仅 1/85 个长宽比大于 2.25，3/85 个最大边小于 36 像素；validation 分别为 0/73 和 3/73。因此“正方形窗口无法匹配极端长脸”或“最小边长门槛直接排除大多数脸”不能单独解释当前漏检。这个比例不能证明框形状没有影响，因为较温和的长宽比、偏移和 NMS 也可能降低 IoU。
- 从最终匹配数尚不能区分：真正没有候选、候选框 IoU 不足、NMS 压掉正确框、HOG/边长删除正确框。这是下一步必须做的逐标注候选诊断。下一轮优先在 train 页按这些失败类型收集和复核困难负样本，扩展/重训 Cascade；在 validation 上同时查看 Precision、Recall、F1 与运行时间，只在配置锁定后做固定 test 评价。`TODO.md` 已把这项用户要求列为下一步，而非冒充原 PDF 的新增强制步骤。
