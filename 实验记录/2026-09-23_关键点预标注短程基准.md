# 实验记录：28 点关键点预标注短程基准

- 日期：2026-09-23
- 目标：用实际短程预标注吞吐量估算 anime256 全量耗时，判断是否需要 GPU 平台
- 输入池：anime256，共 27,588 张 256×256 单脸裁剪图
- 固定抽样：64 张，随机种子 `20260923`，覆盖既有 train/validation/test 清单

## 方法

使用 `anime-face-detector 0.1.0` 的 HRNetV2 28 点模型。由于 anime256 已是一脸一图的裁剪池，直接将整张图作为人脸框输入关键点模型，不重复运行 YOLO。开启默认的水平翻转测试（flip test），以质量优先。

运行命令：

```powershell
.venv\Scripts\python.exe scripts\preannotate_landmarks.py `
  --limit 64 --split all --run-name hrnetv2_cpu_pilot_64
```

运行环境由 `uv` 创建和管理：Windows 11、CPython 3.12.13、PyTorch 2.14.0 CPU、8 个 PyTorch 线程。本机未检测到 NVIDIA 驱动，`torch.cuda.is_available()` 为 false。

## 结果

| 指标 | 结果 |
|---|---:|
| 成功图片 | 64 / 64 |
| 每图关键点 | 28 |
| 批次总耗时 | 7.883 秒 |
| 稳态平均耗时 | 0.1213 秒/图 |
| 稳态中位耗时 | 0.1203 秒/图 |
| 稳态 P95 | 0.1356 秒/图 |
| 稳态吞吐量 | 8.24 图/秒 |
| 模型缓存后的加载耗时 | 0.280 秒 |

模型权重的首次网络获取属于一次性准备开销，不计入全量吞吐量外推。

按稳态平均值线性外推：

```text
27,588 × 0.121347 秒 ≈ 3,347.7 秒 ≈ 55.8 分钟
```

若只处理 train 的 20,710 张，约需 41.9 分钟。以上估算包含逐图读取、推理和 JSONL 写入；实际全量运行应预留 10%～20% 余量，因此全部 27,588 张可按约 1.0～1.1 小时安排。

## 快速质量检查

- 共生成 1,792 个点，所有记录均恰好包含 28 点；
- 模型分数均值 0.8657，中位数 0.9211；该分数是热图响应，不应直接解释为校准概率；
- 4 个点位于图像边界外，占 0.22%。自动结果不做静默裁剪，应在人工修正环节优先检查；
- `visibility` 保持为 `null`，没有把模型分数伪装成人工可见性标签。

## GPU 决策

当前只对 anime256 做一次预标注时，不需要租用 GPU 平台：CPU 全量约一小时，环境已搭好，GPU 环境准备和数据传输带来的收益有限。

如果后续还要把 LAP/Manga109 的十几万至二十多万人脸框全部送入同一关键点模型，或需要多轮调参重复预标注，CPU 预计会增长到约 6～11 小时，此时再使用 GPU 更合理。GPU 的具体加速比应在目标平台用同一脚本复测，不从本次 CPU 数据臆测。
