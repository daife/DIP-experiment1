# 实验记录：数据集整理与标注格式统一

- 日期：2026-09-23
- 实验阶段：实验一前期准备
- 工作目录：`experiment1`
- 记录主题：阅读实验要求，整理已下载数据集，为检测样本生成和 28 点关键点预标注建立可复现的数据基础

## 1. 本阶段目标

本阶段暂不训练模型，主要完成以下准备工作：

1. 阅读根目录中的 Markdown 和 PDF 实验说明，明确数据要求、划分原则和最终标注格式；
2. 盘点 LAP、Manga109 和 anime256 三个已下载数据集；
3. 将压缩包、原始数据、标准化清单、派生数据和预标注结果分层存放；
4. 在不修改原始标签的前提下，将 LAP 与 Manga109 的人脸框转换为统一 JSONL 表示；
5. 按原始来源分组生成固定的 Train/Validation/Test 划分，避免数据泄漏；
6. 检查图片、标签和边界框，记录源数据异常，供后续人工复核。

## 2. 从实验要求中提取的数据约束

实验要求中的数据相关重点如下：

- 检测器使用 `24 × 24` 人脸正样本；
- 负样本必须来自真实动漫或漫画场景，不能只使用随机噪声；
- 正样本应覆盖不同脸型、眼型、发型、画风、轻微旋转和遮挡；
- 推荐按 Train 75%、Validation 10%、Test 15% 划分；
- 同一原图产生的不同裁剪不得跨集合；
- 同一漫画页面或作品中的高度相关样本不应同时出现在训练集和测试集；
- 数据增强只作用于训练集；
- 28 点关键点必须使用固定顺序，并记录遮挡点的 `visibility`；
- 当前没有可直接使用的完整 28 点真值数据集，因此需要“模型预标注 + 人工修正”的半自动流程。

因此，本次整理的核心不是简单解压，而是保存样本的来源关系，并在生成裁剪之前完成分组划分。

## 3. 数据集盘点与用途分析

### 3.1 LAP（Labeled Animation Posters）

- 原始图片数：45,286 张；
- 原始数据大小：约 4.02 GiB；
- 内容：动漫海报及人脸框、头部框；
- 文件名中包含 MyAnimeList 作品 ID，可用于同作品分组；
- `labels_faces.txt`：前 5,000 张图片的人工精修标签，第五个数为类别 ID；
- `labels_faces_baseline.txt`：全部图片的自动检测标签，第五个数为置信度，而不是类别 ID；
- `classes.txt`：15 种人物或面部类别。

LAP 标签原始格式为：

```text
相对图片路径: x1 y1 x2 y2 class_or_score[, x1 y1 x2 y2 class_or_score, ...]
```

计划用途：

- 人脸检测正样本；
- 海报背景、文字、装饰图案等真实负样本；
- Cascade 初始训练后的困难负样本挖掘；
- 有人工标签时优先使用人工精修框，否则显式使用带置信度的自动基线框。

参考项目：<https://github.com/nsndp/labeled-animation-posters>

### 3.2 Manga109-v2026

- 实际图片数：10,602 页；
- 原始数据大小：约 4.04 GiB；
- 最新标注 XML 数：109 份，对应 109 部漫画作品；
- 标准化得到人脸框：118,593 个；
- XML 同时包含人脸、身体、画格、文字等对象，本阶段只提取 `face`；
- 每页图片命名为三位数字，例如 `002.jpg`，XML 中使用对应页码 `index="2"`。

计划用途：

- 漫画人脸检测正样本；
- 漫画页面中的对白框、拟声词、头发、身体、建筑和复杂线条背景负样本；
- 困难负样本挖掘；
- 复杂漫画背景上的通道响应和检测性能测试。

许可注意事项：Manga109 仅限学术用途，不得向第三方再分发；在论文或演示中展示漫画内容时，需要按数据集要求注明作者和数据来源。

### 3.3 anime256

- 图片数：27,588 张；
- 原始数据大小：约 0.68 GiB；
- 图片尺寸：检查结果全部为 `256 × 256`；
- 内容：已经裁剪的人脸图像；
- 原生标签：无边界框、无关键点。

计划用途：

- 人脸正样本补充；
- 28 点关键点模型的预标注与人工修正候选池；
- 不作为场景负样本；
- 不将“图片已裁成人脸”误当作关键点真值。

文件名最后的数字通常表示同一来源图像产生的不同裁剪，因此划分时尽可能去掉最后的裁剪编号，将同源人脸放入同一集合。

参考项目：<https://github.com/learner-lu/anime-face-dataset>

## 5. 统一清单和标注结构

### 5.1 图片清单

`manifests/images.csv` 为每张可用图片保存以下信息：

```text
image_id
image_path
source_dataset
source_group
split
width
height
manual_face_labels
baseline_face_labels
```

`image_id` 在三个数据集中保持全局唯一。后续裁剪、预标注和人工修正都必须保留该 ID 或明确记录父图像 ID，以便回溯原图。

### 5.2 统一人脸框记录

标准化 JSONL 每行代表一张图片，基本结构如下：

```json
{
  "image_id": "manga109:AisazuNihaIrarenai:002",
  "image_path": "raw/manga109/images/AisazuNihaIrarenai/002.jpg",
  "source_dataset": "manga109",
  "source_group": "AisazuNihaIrarenai",
  "split": "train",
  "width": 1654,
  "height": 1170,
  "annotation_source": "manga109_v2026",
  "annotations": [
    {
      "bbox": [1071, 687, 1112, 719],
      "category": "face"
    }
  ]
}
```

边界框统一采用绝对像素 `xyxy` 表示，即 `[x1, y1, x2, y2]`。原始数据仍完整保留，标准化文件只作为后续程序的统一输入层。

### 5.3 后续关键点结构

`annotation_schema.json` 规定后续每张人脸包含 28 个固定顺序关键点，每个点预留：

```text
x, y, visibility, confidence
```

- `visibility = 1`：人工认为关键点可见；
- `visibility = 0`：遮挡、不可见或无法可靠判断；
- `confidence`：模型预标注置信度，与人工可见性分开保存。

## 6. 数据划分策略

使用固定种子：

```text
experiment1-anime-face-v1
```

将 `数据集名 + source_group` 进行 SHA-256 哈希，再按以下阈值分配：

- Train：75%；
- Validation：10%；
- Test：15%。

各数据集的 `source_group` 定义如下：

| 数据集 | 分组单位 | 目的 |
|---|---|---|
| LAP | 文件名中的 MAL 作品 ID | 同一动漫作品的相关海报不跨集合 |
| Manga109 | 漫画作品名 | 同一漫画的所有页面不跨集合 |
| anime256 | 去除最终裁剪编号后的来源标识 | 同一原图裁出的多张脸不跨集合 |

实际划分结果：

| 数据集 | Train | Validation | Test | 合计 |
|---|---:|---:|---:|---:|
| LAP | 33,951 | 4,462 | 6,873 | 45,286 |
| Manga109 | 7,955 | 955 | 1,692 | 10,602 |
| anime256 | 20,710 | 2,758 | 4,120 | 27,588 |
| 总计 | 62,616 | 8,175 | 12,685 | 83,476 |

已检查 40,941 个来源组，每个来源组只对应一个 split，未发现跨集合泄漏。

## 7. 标签统计结果

| 标注来源 | 图片记录数 | 含人脸记录数 | 人脸框数 |
|---|---:|---:|---:|
| LAP 人工精修 | 5,000 | 4,767 | 19,439 |

## 8. 数据质量检查与异常处理

执行了以下检查：

- 图片文件是否存在；
- 图片是否能够读取；
- 图片宽高是否与标签记录一致；
- `image_id` 是否唯一；
- 标准化记录能否回指图片清单和实际文件；
- 边界框坐标是否位于图片范围内；
- 同一来源组是否跨 Train/Validation/Test；
- anime256 是否全部为 `256 × 256`。

检查结果：

- 83,476 张图片均可从清单路径找到；
- 所有图片 ID 唯一；
- 三份标准化 JSONL 均可正确解析并回指原图；
- 未发现 split 泄漏；
- anime256 尺寸检查无异常；
- LAP 人工精修标签中发现 6 个轻微越界框；
- Manga109 XML 中发现 17 个没有对应图片文件的尾页记录。

异常处理原则：

- 不直接修改原始标签；
- LAP 的 6 个越界框继续保留在标准化记录中，并写入 `validation_errors.txt`，后续生成裁剪时应先裁剪到合法边界或人工复核；
- Manga109 的 17 个缺图 XML 记录没有进入可用图片清单和标准化训练记录，但异常被完整记录；
- 不把异常静默删除，以便实验报告说明数据清洗依据。

## 10. 本阶段结论

本阶段将三个用途不同的数据源整理为统一且可追溯的数据入口：LAP 和 Manga109 提供检测框及真实场景，anime256 提供已裁剪的人脸池。与直接随机划分图片相比，先按作品或原图来源分组再划分，可以显著降低同源图像进入不同集合造成的性能虚高风险。

目前数据已经具备后续工作的基础条件：

1. 可根据人工框或高置信度自动框生成 `24 × 24` 检测正样本；
2. 可在 LAP/Manga109 完整场景中采样普通负样本；
3. 可保持 source split 不变地进行困难负样本挖掘；
4. 可对 anime256 及检测框裁剪结果运行 28 点模型预标注；
5. 可将自动标签和人工修正标签分层保存并持续审计。
